# UID 与删除模块精简验收记录

日期：2026-11-18。本轮已完成随机 UID 和 DeletionRequest 生命周期移除。文档先于代码更新，UID 提交为 `914dc10`，模块移除提交为 `4aea797`。

## 已实现行为

- 新邮箱账号未指定 UID 时生成随机 UUID；邮箱修改和确认不再修改 UID。已有非空 UID 和第三方 provider 身份匹配保持稳定，不批量重编号。
- 整体删除 DeletionRequest、DeletionTombstone、Deletions/Lifecycle 服务、删除任务、完成邮件、恢复工具及相关策略、配置、通知和后台页面，不新增替代删除流程。
- 删除申请、查询、取消、后台重试和 `DELETE /users` 均返回404；保留注册、登录、资料修改、成员管理和暂停/恢复。
- 去掉删除专属锁和多余服务包装；保留建队原子事务、团队行锁、锁内权限复验、最后 owner 和并发邀请/所有权保护。
- 保留历史 deleted_at/deleted 访问限制。历史已删除团队的旧邀请页面返回404，不显示团队名称或接受按钮；暂停团队沿用原有行为。
- 后台保留两栏账号/团队统计及失败邮件/通知处理，继续使用 Pundit 和 Ransack。

## 数据与工作区边界

使用独立 PostgreSQL 测试数据库应用迁移 `20261118180000`，并验证导出的 schema 与本轮提交定义一致。迁移删除两个模块表、废弃任务和通知；待删除团队转为暂停，已经进入不可逆阶段的账号/团队保留不可访问标记。迁移不继续执行业务删除或清理外部台账文件。

隔离测试数据库已清理，开发和生产数据库未执行本轮迁移。数据库迁移不可逆，发布前需备份并停止旧 Web/worker；详见 [移除说明](saas-data-lifecycle.md)。

UID 与删除模块修订时，工作区原有的无关 schema 和模型注释修改均已保留，未混入对应提交。完整实施步骤见 [五步计划](saas-implementation-plan.md)。
