# SaaS 数据导出与删除运行说明

本模块服务于 Team/Member SaaS 模板。导出不提供收费额度，删除流程不涉及订阅或支付。

## 数据导出

团队 owner/admin 可以请求导出自己的团队数据。导出包含团队资料与设置、当前成员公开资料、审计记录、文件元数据；**不包含文件内容**、密码、会话令牌、邀请令牌、邮件密文或第三方秘密。格式为带版本号的 JSON。

任务执行前和完成前重新核验发起人的有效成员关系及角色；下载时再次核验。团队暂停后可以进行恢复所需的导出，进入删除冷静期后不再接受新导出。结果仅通过授权 API 下载，生成后 24 小时过期。默认最多 50 MiB，可通过 `MAX_EXPORT_BYTES` 调整；超限任务失败，不提供不完整结果。

`BuildDataExportJob` 使用租约识别过期执行者；`CleanupDataExportsJob` 清理过期结果并补投失败或中断任务，最多尝试 5 次。后台可以查询失败原因，不返回完整异常信息或文件内容。

## 删除请求与保留

- 请求和取消都要求当前密码。团队删除仅 owner 可申请；个人账号只能由本人申请。
- 默认冷静期 7 天，`DELETION_COOLING_DAYS` 可配置为 1—30 天。
- 团队申请删除后进入 `deletion_pending`，立即冻结写入，仍允许 owner 查看和取消请求；取消恢复申请前的 active/suspended 状态。
- 账号冷静期内仍可登录并取消，但不能新建或加入团队、接任团队所有者。申请和执行时都检查最后 owner 约束。
- 删除开始后不可取消。账号停用并撤销凭证；团队进入 deleting 后即从团队查询与文件授权中排除，即使清理或台账写入暂时失败也不会重新开放访问。所有文件、导出结果、成员和邀请、通知、邮件敏感内容按顺序清理；账号和团队保留匿名记录以保存引用关系。
- 审计仅保留必要标识，删除涉及的个人元数据与自由文本原因；审计默认保留 365 天。删除台账长期保留最小标识，不保存邮箱或姓名。
- 完成通知发送到申请时加密保存的邮箱。发送成功后立即清除地址；持续失败的加密地址最多保留至完成后 30 天。

删除任务记录阶段和失败原因，可重复执行。存储删除失败时保留存储键和处理记录；没有确认文件清理成功就不会宣称删除完成。`SweepDeletionsJob` 补投到期、失败及中断任务，最多自动尝试 8 次；超过次数后需管理员排查并通过受控重试入口恢复。

## 独立删除台账

生产环境必须设置 `DELETION_LEDGER_PATH`，指向与数据库备份独立保存、单独备份且权限受限的持久目录。开发环境默认使用 `storage/deletion-ledger`。默认目录不等于已经配置生产备份。

每个不可逆删除操作在开始清理前先写入一个 JSON 台账文件，包含请求 UUID、对象类型、对象 ID、创建时间指纹和删除时间。文件通过临时文件、同步和原子重命名保存。文件不包含邮箱、名称或用户内容。

当目录不可写或同步失败时，任务失败且不开始不可逆清理。禁止把该目录放在临时容器文件系统或与数据库恢复一起回退的位置。

## 备份恢复操作

1. 保持应用入口关闭，恢复数据库和文件服务。
2. 挂载最新独立删除台账目录，确认 `DELETION_LEDGER_PATH` 正确。
3. 如需从当前数据库重新生成缺失的台账文件，运行 `bundle exec rails data:deletions:export`。该步骤不能代替恢复独立台账备份。
4. 运行 `bundle exec rails data:deletions:replay`，在恢复后的数据上重新执行已进入不可逆阶段的删除。成功返回前不要开放应用流量。
5. 检查失败记录、私有附件清理结果和账号状态。若备份早于所有权转移，账号将保持停用，重放会明确失败；由管理员修复团队所有权后再次重放，不能绕过最后 owner 保护。
6. 确认重放成功后再恢复后台定时任务和应用流量，并记录恢复验证结果。

重放校验对象的创建时间指纹，遇到 ID 对应关系不一致时拒绝继续，避免删除不同对象。这一流程提供恢复后的删除重放能力，不自动创建数据库备份，也不声明满足特定法律或认证要求。
