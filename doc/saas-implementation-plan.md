# SaaS 模板精简实施计划

修订日期：2026-11-18。本版按最新要求将新邮箱账号 UID 改为随机值，并整体移除 DeletionRequest 生命周期模块。继续保留90天 JWT、Team/Member、Pundit、自建后台及 Ransack。先更新本文，再执行代码。

## 第一步：随机且稳定的用户 UID

1. 新邮箱账号未提供 UID 时，由服务器生成 `SecureRandom.uuid`，不再使用邮箱作为默认标识。
2. 删除邮箱变更时同步 UID 的回调；确认新邮箱、改密和修改资料不会改变已有 UID。
3. 保留已存储的非空 UID，不批量重编号；第三方 provider 的外部身份匹配继续使用原来的 provider/UID 对。
4. 更新工厂及模型、邮箱确认、资料更新测试，验证随机性、唯一性、稳定性和第三方身份复用。

验收：

- [x] 新邮箱账号获得随机 UUID，两个账号的默认 UID 不同。
- [x] 既有 UID 和第三方身份匹配不被邮箱变更破坏。

## 第二步：整体移除删除生命周期

1. 删除 DeletionRequest、DeletionTombstone、相关 Policy、Deletions/Lifecycle 服务、后台任务、完成邮件与恢复任务。
2. 移除删除申请、查询、取消、重试及台账接口；同时关闭 `DELETE /users`，避免退回 Devise 默认的立即硬删除。
3. 移除冷静期、队列扫描、删除通知类型和环境参数，不创建替代的删除框架或自动删除流程。
4. 去掉建队、接受邀请和转移所有权中的删除生命周期耦合；保留实际业务需要的事务、团队行锁、Pundit 复验和最后 owner 保护。
5. 保留历史 `deleted_at`/`deleted` 标记对应的访问及恢复限制，不使历史已删除账号或团队重新可用。

验收：

- [x] 运行代码不再引用 DeletionRequest、DeletionTombstone、Deletions 或 Lifecycle。
- [x] 原删除入口返回404，普通注册、资料修改、邀请及团队操作仍正常。

## 第三步：清理后台与通知

1. 删除自建后台的删除申请、台账列表/详情及重试入口，删除对应导航和统计。
2. 首页保留账号/团队统计、失败邮件/通知和审计；列表继续使用 Pundit Scope 内的 Ransack 查询。
3. 团队筛选使用 active/suspended/deleted，保留历史已删除团队的查看限制和不可恢复保护。
4. 删除专属通知文案、搜索白名单和废弃测试，将通用任务上下文测试改为邮件或通知任务。

验收：

- [x] 后台和消息中不再提供删除生命周期入口。
- [x] 后台登录、搜索、分页、权限和审计操作通过回归。

## 第四步：前向移除迁移

1. 保留历史迁移，新增迁移删除两个生命周期表及相关旧任务、专属通知；存在仍被 worker 占用的旧任务时拒绝迁移。
2. 对历史删除状态做保守转换：待删除团队转为暂停；已进入不可逆阶段的账号/团队保留不可访问标记，不自动恢复活动状态。
3. 迁移不执行业务删除、匿名化或外部台账文件清理；现有用户、团队和审计记录保留。
4. 本轮在隔离测试数据库验证，不对开发或生产数据库执行破坏性迁移。
5. 工作区已有与本任务无关的 schema/注释修改，保留这些修改；只应用本轮所需的结构差异，不整文件覆盖。
