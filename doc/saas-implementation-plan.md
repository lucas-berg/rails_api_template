# SaaS 模板修订实施计划

修订日期：2026-11-18。本版替代上一版的文件、导出和后台设计。按用户要求，先更新本文及关联文档，再修改代码；验收结果记录在 [saas-validation.md](saas-validation.md)。

## 范围与约定

- 保留 User、Team、Member、Invitation、90 天固定有效 JWT、邮箱验证、可撤销会话、事务邮件、通知、审计和账号/团队删除。
- **Devise/JWT 负责登录身份认证，Pundit 负责访问授权**。权限角色不写入长期 JWT，每次查询与写入重新判断。
- 使用 Pundit 标准两参数 Policy、Scope、authorize 和 policy_scope。移除自定义 Authorization 分派器及平台授权适配器，不再维护第二套权限框架。
- **移除 Document、上传、下载、预览、头像和业务数据导出**，包括关联接口、后台入口、任务、配置、统计、通知、测试及专属依赖。
- **移除 ActiveAdmin** 及其专属前端依赖；以普通 Rails 控制器、ERB 和独立样式实现 `/admin`。
- **保留 Ransack** 作为新版 `/admin` 的搜索工具。先应用 Pundit 的数据范围，再执行 Ransack 查询；各模型明确允许搜索的字段，不开放密码、令牌、密文或任意关联遍历。
- 保留 owner/admin/member/viewer 与平台 super_admin/support。平台身份与团队身份分别授权。
- 保留新 API 的 data/meta/errors 约定、现有认证/资料响应外壳及敏感字段白名单。
- 不新增支付、商业配额、API Key、Webhook、SSO、通用导入或完整用户控制台。

## 第一步：移除文件和导出功能

1. 删除 Document/DataExport 模型、策略、展示器、上传/文件/头像/导出控制器及相应路由。
2. 删除格式检测、存储上传、清理、导出构建服务和任务，去掉 GoodJob 周期扫描与废弃环境参数。
3. 清理 User/Team 关联、头像字段引用、工作台文件计数和后台资源；删除 export.ready 通知种类和翻译。
4. 保留历史迁移，新增前向移除迁移：删除 avatar 外键/字段和两个业务表；归并旧删除检查点；清理这两个模块的历史通知、任务和附件关联元数据。
5. 不用迁移删除磁盘/对象存储中的文件内容。保留 Rails 原有通用 Active Storage 表并关闭公共存储路由，避免影响历史存储数据。
6. 删除专属测试与样例；通用任务上下文、删除和后台测试改用保留的业务对象。

验收：

- [ ] 已移除的公开路径返回 404，摘要和后台不再出现文件/头像/导出。
- [ ] 新旧数据库结构可前向迁移，剩余模型不依赖废弃字段。
- [ ] 通用后台任务和删除流程无悬空类或旧检查点。

## 第二步：采用 Pundit 授权

1. 添加 Pundit，保留 Devise/JWT 和 90 天有效期；将登录与授权的职责在文档和代码中分开。
2. 将团队、成员、邀请、通知及自身资源改为标准 Policy/Scope。使用已授权团队关联加载对象，维持跨团队 404。
3. 控制器调用 authorize/policy_scope，并检查是否遗漏授权；创建资源时由服务器确定归属，不信任客户端 team_id。
4. 写入服务在原有事务和锁内刷新操作者并再次调用 Pundit；服务被任务或后台直接调用时仍执行授权。
5. 平台使用 Admin 命名空间策略和 current_admin_user，support 只读，super_admin 执行显式允许的操作。
6. 删除旧策略分派、第三个权限上下文参数和 ActiveAdmin 授权适配器，避免双轨兼容层。

验收：

- [ ] 无认证、跨团队、自我提权、admin 管理 owner/admin、support 写操作均被拒绝。
- [ ] 邀请接受不要求预先加入团队，但必须令牌有效、邮箱已验证且匹配。
- [ ] 保留最后 owner、成员并发、删除并发和旧 JWT 即时失权测试。

## 第三步：自建 /admin dashboard

1. 删除 ActiveAdmin gem、初始化器、app/admin DSL 和专属 JS/CSS、NPM 依赖。
2. 使用 AdminUser 的 Devise 登录，保留 `/admin/login`、`/admin/logout` 及密码重置；提供独立登录和后台布局，保留 CSRF。
3. 首页展示真实用户/团队数量、失败邮件/通知/删除任务以及近期审计；提供清晰导航、空状态、分页和查询入口。
4. 为账号、团队、成员、邀请、会话、审计、邮件、通知、删除申请/台账及平台管理员提供明确的控制器与字段白名单。
5. 保留封禁/恢复、邮件/通知/删除重试和平台管理员维护；修改必须填写原因，业务与审计同事务提交。无硬删除和批量写入口。
6. 拒绝未经定义的 JSON/CSV 导出；不显示令牌摘要、密码摘要、密文、租约或内部存储键。
7. GoodJob/Flipper 独立入口只允许 super_admin；登录限流覆盖新的实际路由。
8. 列表使用 Ransack 标准 `q[...]` 参数及搜索表单，保留分页和筛选条件。审计动作使用 `q[action_eq]`，避免与 Rails 路由的 `action` 参数冲突；测试组合筛选、无匹配结果和敏感字段限制。

验收：

- [ ] 实际浏览器可登录、查看首页、导航和提交允许的操作。
- [ ] support 不能通过直接请求或隐藏入口修改数据。
- [ ] 未授权请求、敏感信息、无原因操作和审计失败回滚均有测试。
- [ ] Gemfile/锁文件、前端依赖和运行代码无 ActiveAdmin 引用。
- [ ] Ransack 后台搜索可用，且不能扩大 Pundit 授权范围或搜索敏感字段。

## 第四步：精简剩余代码

1. 去掉仅为已删除模块服务的类、helper、配置和通用分派器；单一调用点的薄包装能直接表达就直接表达。
2. 将单一模型的零散关联/偏好配置收回模型；保留职责明确的认证模块，避免把安全逻辑挤入控制器。
3. 后台使用普通 Rails 页面和少量共享 partial，不再创建资源注册器、动态模型加载或替代 ActiveAdmin 的内部框架。
4. 删除流程收敛为 requested → ledger → records → completed，保留冷静期、唯一 owner、不可逆阶段、匿名化和重放保护。
5. 保留确有必要的事务边界、并发锁、任务租约、审计、发件箱、来源请求关联和失败恢复；精简不以删掉保护为代价。
6. 移除后台独占、已无使用点的依赖；保留 Ransack 及各模型的最小搜索白名单，不增加通用搜索分派器，不趁机改动无关业务行为。

验收：

- [ ] 不存在旧新权限并行、空兼容壳或动态资源框架。
- [ ] 删除台账重放和通知/邮件重试仍可执行。
- [ ] 搜索全仓库时，废弃功能引用仅出现在必要的历史/清理迁移或历史说明中。

## 第五步：回归与交付

1. 在测试数据库执行移除迁移；核对 schema、外键、旧任务和阶段数据转换。开发/生产数据不在本轮自动清空。
2. 运行相关行为测试、完整 RSpec、真实浏览器后台流程和全部代码检查。
3. 更新模型注释，从空临时文件生成 OpenAPI；核对剩余路由和响应，不保留删除接口。
4. 构建前端和 Docker 镜像；隔离验证 Web/PostgreSQL/Redis 启动与就绪检查。
5. 更新 README、features、运行手册和验收记录，按文档、模块移除、Pundit、自建后台和验证拆分提交。

验收：

- [ ] 全量测试与代码检查通过，OpenAPI 和注释无漂移。
- [ ] 前端与容器构建通过，工作区只包含本任务变更。
- [ ] 文档准确区分当前能力、已删除功能和生产运维准备。
