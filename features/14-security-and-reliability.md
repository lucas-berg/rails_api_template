# 安全、异步任务与运行保障

当前范围（2026-11-18）：文件、头像和业务导出已移除；使用自建 /admin、Pundit 授权及 Ransack 搜索。实现边界见 [五步计划](../doc/saas-implementation-plan.md)，测试与构建结果见 [验收记录](../doc/saas-validation.md)。

- 优先级：P0。
- 当前状态：共享限流、健康检查、任务恢复、请求/任务上下文与运维说明已实现；生产监控和灾备仍需部署核验。
- 依赖：贯穿当前五步；不依赖支付、商业计量或公开 API Key。

## 入口保护

- Rack::Attack 使用共享 Redis 计数，不能替换为各进程独立内存存储。登录按 IP、确认/找回按规范化邮箱摘要限制，邀请发送/重发在权限校验后按团队限制。
- 429 提供 Retry-After；参数含非 JSON 标量、认证路径后缀等绕过情况有针对性测试。Redis 不可用不应默默取消安全限制，需按手册恢复依赖。
- JSON 使用 Bearer，浏览器保留 CSRF；CORS/HTTPS/Cookie 和公开链接按部署环境配置。密码、令牌、恢复链接和加密邮件内容不进入普通日志。
- `/api/v1/status` 检查进程存活，`/api/v1/ready` 检查运行依赖；公开响应不披露凭据和异常堆栈。

## 异步任务与可观测性

- GoodJob 驱动事务邮件和通知；相关意图持久化在数据库，after_commit 入队失败由扫描任务恢复。
- 每类任务有租约/执行锁、有限重试和终态失败，不把 GoodJob 重试等同于恰好一次。重试前根据数据库当前状态重新判断权限和资格。
- 请求和任务日志关联 request_id、job_id、user_id、team_id；异步序列化来源 request_id。每个 Job 从受信记录重建上下文，结束时清理；全局扫描不残留上个团队上下文。
- 自建 Rails /admin 展示失败邮件和通知投递；super_admin 提供原因后使用受控重试。任务/开关管理入口不能由普通业务用户或 support 写入。
- Sentry、Lograge 等已有依赖不等于已完成生产接入、告警和响应流程。

## 恢复与上线

[运行手册](../doc/saas-operations.md) 说明环境变量、数据库/Redis/SMTP、任务扫描、限流和故障排查；[模块移除说明](../doc/saas-data-lifecycle.md) 说明删除生命周期退役的迁移边界。

1. 发布采用兼容迁移和约束核验；历史邮箱不自动确认，业务数据归属不能随意回填。
2. 配置生产密钥、共享 Redis、邮件与任务进程，验证真实请求和失败重试。
3. 设置错误率、延迟、队列积压、失败投递/清理的告警阈值与负责人，完成实际告警投递。
4. 制定数据库备份；恢复时先关闭流量、验证数据与账号状态，再恢复服务。
5. 记录实际 RPO/RTO、容量和恢复演练结果。当前仓库不承诺已验证的生产 SLO，也没有自动备份实现。
