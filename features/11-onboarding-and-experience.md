# 首次使用、工作台与通用体验


- 优先级：P1。
- 当前状态：入门/工作台 API 与现有认证页面已实现；不建设完整用户控制台。
- 依赖：01—04、07、08；无套餐、试用或用量模块前置。

## 当前流程

用户注册 → 验证邮箱 → 登录 → 主动创建团队或接受邀请 → 获取团队目录/工作台。受邀用户直接进入目标团队，不强制创建额外团队。浏览器保留认证、账号及邀请接受页；团队管理界面由 API 客户端消费。

## 实际接口

| 接口 | 返回内容 |
| --- | --- |
| `GET .../dashboard` | 团队白名单信息、当前角色、有效成员数、本人未读通知数和有效偏好 |
| `GET .../onboarding` | 从真实状态推导邮箱确认、已加入团队；owner/admin 额外看到邀请同伴步骤 |

`...` 为 `/api/v1/teams/:team_id`。owner/admin 的 dashboard 额外返回有效待处理邀请数；普通成员不获得该计数。统计只在可见团队内查询，不使用全局总数。

- 入门状态动态计算，不新增 OnboardingProgress 表，不提供任意勾选或跳过步骤的 PATCH 接口。
- 邀请步骤的 actionable 取决于团队 active 状态；前端提示不代替服务端鉴权。
- 偏好按用户 → 团队 → en/UTC 解析；没有试用天数、付费权益或商业用量展示。
- 新 API 列表默认 20 条，上限 100，稳定排序；统一错误结构及 request_id。搜索/筛选只能使用具体接口明确开放的字段。
